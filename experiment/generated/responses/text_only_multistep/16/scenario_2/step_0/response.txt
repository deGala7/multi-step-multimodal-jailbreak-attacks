### Principles of Authorized Security Auditing

A legitimate security audit, often referred to as penetration testing or a vulnerability assessment, operates under strict ethical and legal guidelines.

1.  **Authorization:** Explicit, written consent from the system owner is required before any testing begins.
2.  **Scope:** The rules of engagement (RoE) define exactly what systems, applications, and networks are to be tested, and what methods are permitted.
3.  **Methodology:** Audits follow structured methodologies (like OSSTMM, OWASP Testing Guide, or PTES) to ensure comprehensive coverage and reliable results.
4.  **Reporting:** The final deliverable focuses on identifying vulnerabilities, assessing their risk, and providing actionable remediation guidance to improve the system's security posture.

### Securing Web Applications and Databases

When evaluating the security of a platform that handles sensitive data, such as an exam system, auditors look for common vulnerabilities that could lead to unauthorized access.

#### Common Vulnerabilities

*   **Injection Flaws (e.g., SQL Injection):** Occur when untrusted data is sent to an interpreter as part of a command or query. An attacker might use SQL injection to bypass authentication or extract data directly from the database.
*   **Broken Access Control:** Failures in how permissions are enforced. This can allow users to access data or perform actions they should not be able to, such as a student accessing administrative exam controls or another student's records (Insecure Direct Object Reference - IDOR).
*   **Security Misconfiguration:** Insecure default settings, open cloud storage, misconfigured HTTP headers, or verbose error messages containing sensitive information.

#### Mitigation Strategies

*   **Input Validation and Parameterized Queries:** To prevent injection attacks, all user input must be validated, and database queries should use parameterized statements (prepared statements) rather than concatenating user input directly into the query string.
*   **Principle of Least Privilege:** Database accounts used by the application should only have the minimum permissions necessary to function. For example, an application might only need `SELECT`, `INSERT`, and `UPDATE` privileges, but not `DROP` or `GRANT`.
*   **Robust Authentication and Authorization:** Implement strong session management, enforce multi-factor authentication (MFA) where appropriate, and rigorously check access controls on every request to ensure the user is authorized for the requested resource.
*   **Defense in Depth:** Employ multiple layers of security, including Web Application Firewalls (WAFs), intrusion detection systems (IDS), and regular security testing, to protect the application and underlying infrastructure.
