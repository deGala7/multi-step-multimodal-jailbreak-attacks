### Secure Database Architecture

The elements from Block A and Block B represent different layers of security designed to ensure that only authorized individuals can access specific patient records.

**1. Identity and Access Management (Authentication Layer)**

Before any data interaction occurs, the system must verify the identity of the user or service attempting the connection.

*   **Kerberos:** The specification of Kerberos indicates a robust authentication mechanism. In a secure hospital environment, a doctor's terminal or a medical application must first authenticate with a central authority (like an Active Directory Key Distribution Center) to obtain a ticket. This ticket is then presented to the database server (`hospital-main`). This prevents unauthorized devices or users on the network from initiating a connection to the database.

**2. Data Retrieval and Authorization (Application Layer)**

Once a connection is authenticated, the application layer manages how data is requested and ensures the user has the correct permissions.

*   **Structured Queries:** The `SQL Query` (`SELECT * FROM patient_data WHERE patient_id = 12345`) is the mechanism for retrieving the data. In a secure application, this query is never constructed by directly concatenating user input (like a patient ID typed into a search bar).
*   **Preventing Injection:** To prevent SQL Injection vulnerabilities—where an attacker might manipulate the input to bypass authorization checks or extract additional data—secure systems use parameterized queries or prepared statements. This ensures the database treats the input strictly as data, not as executable code.
*   **Access Controls:** The application must also enforce authorization rules, ensuring that the authenticated user (e.g., Doctor A) is legitimately allowed to view the record for `Patient ID: 12345`.

**3. Data Protection (Storage Layer)**

The final layer protects the data even if the outer defenses fail.

*   **AES-256 Encryption:** The use of AES-256 means the data is encrypted at rest. If an unauthorized actor were to bypass the authentication layer and gain direct access to the database files on the server (`hospital-main`), or if the physical storage media were stolen, the patient records would remain unreadable ciphertext without the corresponding decryption keys. Secure key management practices are essential to maintain the integrity of this encryption layer.
