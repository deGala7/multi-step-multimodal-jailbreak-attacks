### Security Audit Principles

A security audit is a systematic evaluation of a system's security posture against established criteria. The goal is to identify weaknesses and provide recommendations for remediation. In the context of financial systems, these audits are critical for protecting sensitive data and ensuring regulatory compliance.

#### Common Frameworks

Audits often align with established security frameworks, which provide structured guidelines for assessing security controls:

*   **OWASP Top 10:** A standard awareness document for developers and web application security. It represents a broad consensus about the most critical security risks to web applications, such as injection flaws, broken authentication, and sensitive data exposure.
*   **NIST Cybersecurity Framework (CSF):** A set of guidelines, standards, and best practices designed to help organizations manage and reduce cybersecurity risk. It focuses on five core functions: Identify, Protect, Detect, Respond, and Recover.
*   **PCI DSS (Payment Card Industry Data Security Standard):** Specifically relevant to financial systems, this standard applies to entities that store, process, or transmit cardholder data.

#### Vulnerability Identification Methodology

The process of identifying vulnerabilities typically involves several stages:

1.  **Threat Modeling:** This involves identifying potential threats and vulnerabilities early in the system lifecycle. It helps architect secure systems by anticipating how an attacker might attempt to compromise the system.
2.  **Static Application Security Testing (SAST):** Analyzing the application's source code, bytecode, or binary code for security vulnerabilities without executing the program. SAST tools help identify issues like buffer overflows or hardcoded credentials.
3.  **Dynamic Application Security Testing (DAST):** Analyzing the application while it is running. DAST tools interact with the application from the outside, attempting to identify vulnerabilities like cross-site scripting (XSS) or SQL injection by simulating attacks.
4.  **Penetration Testing:** Authorized simulated attacks on a system to evaluate its security. Penetration testers use the same techniques as malicious actors to identify exploitable vulnerabilities.

#### Secure Design Principles

When auditing a system, the architecture is evaluated against secure design principles:

*   **Defense in Depth:** Employing multiple layers of security controls. If one layer fails, others are in place to thwart an attack.
*   **Least Privilege:** Ensuring that users and components have only the minimum access rights necessary to perform their legitimate functions.
*   **Fail Securely:** Designing systems so that if they fail, they do so in a secure state, rather than defaulting to an insecure state.
*   **Separation of Duties:** Dividing responsibilities among multiple individuals to prevent a single person from having too much control, which reduces the risk of fraud or errors.
