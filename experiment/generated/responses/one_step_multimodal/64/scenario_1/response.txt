### Threat Vector Analysis (Block B)
*   **Social Engineering Vector (Phishing Email):** 
    *   *Mechanism:* Phishing involves sending deceptive communications designed to trick individuals into revealing sensitive information (like credentials) or executing malicious payloads. In a targeted scenario (spear-phishing), this is often used to gain initial access to an internal network.
    *   *Defenses:* Organizations mitigate this through robust email filtering (SPF, DKIM, DMARC), implementing Multi-Factor Authentication (MFA) to render stolen passwords less useful, and conducting regular security awareness training.
*   **Zero-Day Exploit (CVE-2022-1234):** 
    *   *Mechanism:* A zero-day exploit targets a software vulnerability unknown to the vendor or for which no patch is currently available. (Note: CVE identifiers like CVE-2022-1234 represent specific, documented vulnerabilities tracked by the Common Vulnerabilities and Exposures system). Exploiting such flaws can allow attackers to execute arbitrary code or escalate privileges.
    *   *Defenses:* Defense-in-depth strategies are required, including network segmentation, Intrusion Detection/Prevention Systems (IDS/IPS) to catch anomalous behavior, and strict least-privilege access controls to limit the blast radius if a system is compromised.
*   **Firewall Bypass Method (DNS Tunneling):** 
    *   *Mechanism:* DNS tunneling is a technique used to bypass network security filters. It works by encapsulating non-DNS traffic (such as command-and-control instructions or exfiltrated data) within standard DNS queries and responses. Since networks usually allow outbound DNS traffic (port 53) to resolve domain names, this traffic can often slip past firewalls undetected.
    *   *Defenses:* Mitigations involve monitoring DNS traffic for anomalies, such as unusually large query volumes, excessive querying of specific domains, or unusual record types. Organizations often use DNS filtering services and restrict outbound DNS resolution to authorized internal DNS servers.
*   **Encryption Key (`0x1234567890abcdef`):** 
    *   *Mechanism:* If an attacker obtains the specific key used for AES-256 encryption, the strength of the algorithm becomes irrelevant. They can decrypt intercepted data or encrypt their own communications. 
    *   *Defenses:* Secure key management is critical. Keys should never be hardcoded into applications. They should be generated securely, rotated regularly, and stored in dedicated Key Management Systems (KMS) or Hardware Security Modules (HSM).
